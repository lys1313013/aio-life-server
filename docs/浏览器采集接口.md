# 浏览器采集接口（直接保存原业务，2026-10-28）

所有路径前缀 `/api`，Bearer 鉴权，响应 `{code:0,message:null,data:...}`。ID 为字符串，金额为最多两位小数的十进制字符串，日期时间 `YYYY-MM-DD HH:mm:ss`。

豆瓣写入原 `read_record` / `movie`；购物写入原 `device` / `wardrobe_item`，两表新增来源平台、订单ID和商品ID。不创建支出，不保存订单正文或商品快照，不把系统 JSON 塞入备注。图片仍使用 `/file/upload`，业务类型 `read/movie/device/wardrobe_item`。

## 豆瓣

`POST /capture/douban/preview`

请求 `{url,metadata?:{title,author,director,type,totalProgress,coverImgUrl}}`。
响应 `{draft:{url,mediaType,subjectId,title,author?,director?,type,totalProgress?,coverImgUrl?,status,currentProgress},existing:null|{id,version,fields:{...}},warnings:[]}`。

当前页候选信息完整时直接预览；缺标题时调用既有元数据解析能力，禁止预览上传封面或写业务记录。查重直接读取原书影表的豆瓣 URL。

`POST /capture/douban/commit`

请求 `{url,idempotencyKey,action:"create"|"update",existingId?,version?,fields:{title?,author?,director?,type?,totalProgress?,currentProgress?,status?,remark?,rating?,fileId?}}`。
响应 `{id,mediaType,operation:"created"|"updated"|"existing",version,replayExpiresAt?}`。

创建需要标题、类型；更新必须提供现有 ID 和版本，只更新显式字段。状态为 `not_started/in_progress/completed/on_hold`；影视类型 1..5，书籍类型 1；个人影视评分 1..5 或 null，绝不把豆瓣公共评分当个人评分。`title` 最长255，作者/导演100，备注1000，fileId32；空字符串fileId清空封面。原用户表的用户行锁串行化同一用户的书影写入，不新增来源表。普通创建、MCP、豆瓣导入共用查重规则，已有历史重复时要求先处理。

### 豆瓣原生标记自动同步

`POST /capture/douban/sync`

```json
{"url":"https://movie.douban.com/subject/1292052/","idempotencyKey":"本次已确认操作的唯一键","status":"completed","metadata":{"title":"肖申克的救赎","director":"弗兰克·德拉邦特","type":1,"totalProgress":142,"coverImgUrl":"https://img.doubanio.com/view/photo/s_ratio_poster/public/p480747492.jpg"}}
```

只支持影视，必须由插件确认豆瓣原生操作已经成功后调用；页面加载、点击按钮但尚未保存都不能触发。`status` 为 `not_started`（想看）、`completed`（看过）、`removed`（取消标记）。`metadata` 可选，字段只接受标题、导演、类型、总进度与封面地址，不接受个人评分和备注。

响应 `{id:string|null,mediaType:"movie",operation:"created"|"updated"|"unchanged"|"deleted"|"absent",status,replayExpiresAt?,warnings?}`。

- 无影片时，想看/看过写入原 `movie`；候选标题缺失时补充解析元数据，仍无法取得标题则失败。新建不填个人评分，完成时进度设为总进度（已知且大于0）、记录完成时间。
- 已有影片时，仅改变状态、必要的当前进度及完成时间，保留标题、导演、类型、总进度、封面、个人评分、备注与历史开始时间。想看将进度归零并清空完成时间；看过有已知总进度时填满进度。相同状态返回 `unchanged`，不写审计时间，也不抓取元数据或封面。
- 取消标记使用原 `is_deleted` 逻辑删除当前用户对应影片，保留原行与个人数据；返回 `deleted` 与原ID，无记录则为 `absent` 与null。取消操作不需要元数据，不抓图，不删除其他用户或文件。再次标记会创建新的有效影片；有效期内重放旧取消请求只返回旧结果，不会删除后来重新创建的记录。
- 新建的可选封面复用既有豆瓣CDN白名单、禁止跳转、图片格式/大小校验与上传服务。上传使用独立事务；封面失败不影响影片状态保存，以 `warnings` 提示。已完成的独立上传与电影主事务并非同一个事务；极端情况下主事务随后失败，可能留下未关联的已上传文件；不会因此重复创建影片。

接口复用当前用户菜单锁、原用户行锁和下文24小时请求重放机制。它只同步当前用户这个豆瓣条目的状态，不同步豆瓣短评或公共评分，不添加任何表或字段。

## 购物页面预填并直接创建设备/衣物

`POST /capture/purchase/preview`

请求草稿：
```json
{"platform":"jd","orderNo":"9007199254740993555","sourceUrl":"https://details.jd.com/normal/item.action","shopName":"店铺","orderStatus":"paid","paidAmount":"10.01","paidAt":"2026-10-22 12:30:00","items":[{"sourceItemId":"sku:100000001|spec:规格","sku":"100000001","title":"商品","spec":"规格","quantity":2,"paidAmount":"10.01"}]}
```

`platform` 为 `jd/taobao`；`orderNo` 预览可空，提交必填，最多100字，保存原始字符串。选中保存的商品 `sku` 必填（商品ID，最多100字），只接受字母、数字、下划线、连字符，不转换为数字。`sourceItemId` 和 `unitIndex` 仅用于当前请求和页面映射，不入库，也不参与持久来源身份。`sourceUrl` 只允许匹配平台的 HTTPS URL，服务端去除 PassKey 等非身份查询参数。可选 `orderedAt/freight/discount`，每条商品可选 `sku/imageUrl`。页面支付状态支持 `paid/completed/unpaid/refunded/partial_refund/presale/unknown`，不自动推断退款净额。

响应 `{draft,warnings,existingAssets:[{sourceItemId,unitIndex,kind,id}]}`。按当前用户、平台、订单ID读取设备和衣物，再按商品ID分组，以已有数量匹配当前页面条目，不保存明细行或件序号。预览无数据库写入，不返回其他用户或锁定模块中的物品。

`POST /capture/purchase/commit`

```json
{"idempotencyKey":"本次请求唯一键","order":{},"amountConfirmed":true,"assets":[{"sourceItemId":"line:0","unitIndex":1,"kind":"device","fields":{"name":"鼠标","type":"设备类型字典ID","status":"1","fileId":"本人已上传图片ID"}},{"sourceItemId":"line:0","unitIndex":2,"kind":"wardrobe","fields":{"name":"衣物","categoryId":"衣柜分类ID"}}]}
```

`order` 是人工确认后的完整预填草稿。商品行 `paidAmount` 是该行全部件数金额，商品金额合计必须等于草稿实付；未识别时用户补齐。每件价格按分分配，余分分配给前几件，合计守恒。购买日期优先 `paidAt`，其次 `orderedAt`，都没有则留空。只提交用户选择的物品，`assets` 至少1件、最多500件；同一行的每一件最多创建一次，`unitIndex` 为1..quantity。

设备可填 `name/fileId/type/status/remark`；衣物可填 `name/fileId/categoryId/color/brand/size/memo`。设备名称255字，衣物名称100字，尺码20字；设备状态1使用中/2已损坏/3已送人/4吃灰中。分类、文件检查当前用户权限和业务类型。

响应 `{operation:"created"|"existing"|"mixed",createdCount,existingCount,assets:[{sourceItemId,unitIndex,kind,id}],replayExpiresAt?}`。

先锁当前用户行，再通过 Mapper 当前读设备与衣物来源。同商品按已有数量返回原ID和原归属，不覆盖名称、状态、备注和封面；即使请求换成另一物品类型也不会重复创建或改变归属。按选中数量补建缺失物品，全部在同一事务内完成。同商品的规格行和第几件不再保留固定对应关系。补录时，页面用可选 `existingId` 明确保留已显示物品，余下选择只创建不足数量；该ID必须属于当前用户及当前来源商品，已删除则拒绝重建。不同请求键、不同浏览器的并发提交同样查重。逻辑删除记录不参与匹配，可重新录入；迁移前来源为空的记录无法自动关联，不推断或回填。

所有设备/衣物创建同一数据库事务，一件失败全部回滚。不接受 `expense/version/mode/link/id` 等采购持久化或关联操作。没有 `/capture/purchase/{id}`、采购历史查询或补录。

`GET /capture/options` 返回 `{deviceTypes:[{id,name}],deviceStatuses:[{id,name}],wardrobeCategories:[{id,name}]}`。锁定模块不泄露选项。没有费用字典和关联搜索接口。

## 短期重试和结果不确定

Redis 只缓存请求指纹和返回结果24小时。购物来源查重另由设备／衣物表的来源字段和用户行锁保证，不依赖 Redis 结果保留时长。

1. SQL写入之前保留PENDING；Redis不可用时拒绝开始写入。
2. 明确事务回滚后删除PENDING，允许原请求重试；事务结果未知时保留PENDING。
3. 数据库提交后才缓存返回结果；相同键和请求在有效期内返回原结果，同一键换内容拒绝。
4. 提交已成功但缓存结果失败时，保留PENDING；当前响应仍有已保存的业务ID，同时返回 `retryStatus:"unconfirmed"` 和 `warnings`，不返回replayExpiresAt。用户应核对这些ID，不能自动换键再写。
5. 遇PENDING/结果不明，重试返回冲突并要求检查设备、衣柜或书影记录；当前页面仅在内存保留原请求键和内容，不持久化草稿；刷新或关闭后从服务器重新查询来源物品。
6. 请求缓存过期后，购物采集仍按来源字段查重；按当前选中数量复用已保存物品的ID。未知来源的历史记录不做名称或价格猜测匹配。

菜单锁按实际原业务检查：设备 `/my-hub/device`、衣柜 `/wardrobe`、书影 `/record/read` 或 `/record/movie`。购物录入不依赖支出模块解锁。
