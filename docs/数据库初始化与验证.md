
`info`/`validate` 验证迁移历史，不代表真实结构完全一致。`mvn -f tools/flyway/pom.xml verify` 自动创建隔离 PostgreSQL 18，验证新库、重复迁移、增量数据保留、失败事务回滚和拒绝未知非空库，并生成 v6 PostgreSQL 结构契约。已有 PostgreSQL 首次接入必须执行真实结构预检：

```bash
mvn -f tools/flyway/pom.xml compile exec:java -Dexec.args=preflight -Dschema.contract=/private/path/contract.json
```

只有版本和当前 SQL 摘要匹配、真实结构完全一致时才允许显式 `baseline -Dschema.contract=...`。默认禁用自动 baseline、clean、outOfOrder 和跳过执行。不要使用 repair 掩盖结构差异；失败先查看事务和迁移历史，再新增修复版本。

测试不得连接业务库。H2 只承担局部单元测试；PostgreSQL 专属 SQL、并发、事务与约束必须在真实隔离 PostgreSQL 验证。迁移成功和镜像构建成功均不代表运行环境已切换。

## 附件四表升级

已有库升级按以下顺序执行；2026-11-16 的实际执行结果记录在本节末尾：

1. 停止应用、后台任务和其他写入端，备份 PostgreSQL 与对象存储。
2. 显式指定目标库，通过独立 Flyway 执行到准备版本：`mvn -f tools/flyway/pom.xml compile flyway:migrate -Dflyway.target=20261116.10`。
3. 在独立 Python 虚拟环境安装 `tools/attachments/requirements.txt`，通过环境变量提供 `FLYWAY_URL/FLYWAY_USER/FLYWAY_PASSWORD` 和 `AIO_LIFE_MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET_NAME`（均使用完整 `AIO_LIFE_MINIO_` 前缀）。执行 `python tools/attachments/prepare.py --stopped-writes`。
4. 准备工具读取实际字节，生成并校验内容寻址副本，回填对象引用、图片尺寸和附件新 ID；原存储路径保留作为迁移回退依据。工具失败会回滚数据库准备写入，已复制的相同字节可安全复用，修复原因后重跑。
5. 执行 `mvn -f tools/flyway/pom.xml compile flyway:migrate flyway:validate`，应用切换版本之后再恢复写入。`V20261116_11` 对未完成准备的数据主动拒绝执行，失败保持准备完成前结构；不能用 `repair` 绕过准备门禁。

空库可直接执行完整迁移链。整个升级不使用数据库外键，不在应用启动时执行迁移。新旧 ID 不保留运行兼容；客户端与后端需一起切换。成功来源永久复用；未绑定附件 7 天后清理，最新失败任务保留供重试。隔离环境验证入口为 `mvn -f tools/flyway/pom.xml verify -Dit.test=AttachmentMigrationIT`。

历史文件缺失时默认停止准备。仅当确认存储返回 404、附件未绑定且最后修改已超过 7 天时，可通过 `--archive-missing-unbound /安全备份目录/missing-unbound.json` 保留其完整原始元数据，并将原行标记为已删除后继续；不删除记录、不伪造对象。有效附件仍由 `ck_attachment_object` 强制具有物理对象引用，已删除的历史缺失附件允许无对象。绑定中的文件、近期上传以及权限或网络错误不得绕过。

准备工具读取历史图片尺寸时不完整解码、不压缩重编码，也不将新上传的 1600 万像素预算套用到已有文件；原始字节和真实尺寸保持。新上传和远程导入在写入时校验图片；预览依据已确认的对象 MIME 流式返回原始字节，不重新解码或套用上传的像素预算。历史伪装图片的非图片字节及当前不支持的图片格式按 `application/octet-stream` 保存，不能内联。
