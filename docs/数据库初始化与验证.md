# 数据库初始化与验证

数据库迁移统一使用 Maven、Flyway 和 Java 21。Flyway 管理迁移顺序、校验和及执行记录；Java 保留真实结构预检，JUnit/Testcontainers 验证初始化与升级。应用启动不自动迁移，迁移工具不进入应用依赖。

## 工具与目录

SQL 目录入口见[sql/README.md](../sql/README.md)。冻结脚本中的历史版本兼容说明、路径或旧执行入口注释仅用于追溯；实际执行以本指南和 Flyway 版本记录为准，不按旧注释另排执行顺序。

- 独立入口：[tools/flyway/pom.xml](../tools/flyway/pom.xml)，固定 Flyway `13.11.1` 与 MariaDB Connector/J `3.5.11`，仅支持 MySQL 8.x（最低 8.0.16），持续验证 8.0.40 / 8.4.2。需要 Maven、Java 21；集成测试另需 Docker。
- 新库采用 `sql/migrations/B20261028_00_001__mysql_compatible_baseline.sql`：保留已冻结的文件名、内容和校验和，不合并 `01` 至 `04`。原 `B20261028_00__baseline.sql` 及全部旧 V 保持不变；117 已登记至 `.06`，不会执行新增 B。日常仍新增 V，只有用户选定节点才合并业务增量生成完整新基线。
- `sql/migrations/V*.sql` 统一管理结构与种子，由 Flyway 排序。历史结构增量为 `20261028.01` 至 `.04`，种子为 `.05.001` 至 `.05.023`，`.06` 补齐定时任务菜单；`20261029.01` 在历史接入边界后补齐仍缺失的采集来源字段。
- [MigrationGuard](../tools/flyway/src/main/java/top/aiolife/migration/MigrationGuard.java) 是 Flyway Java 回调，校验登记条件及安全配置；[SchemaTool](../tools/flyway/src/main/java/top/aiolife/migration/SchemaTool.java) 提供只读结构预检。
- 迁移相关 Python 执行器、预检器和测试已移除。银行/地区资料生成器属于离线数据加工，输出待审阅 SQL，不参与迁移，也不覆盖已执行版本。

以下命令均在后端仓库执行。先创建目标数据库，设置连接环境变量；密码由终端安全输入或 CI Secret 注入，不写入参数、仓库或报告：

```bash
export FLYWAY_URL='jdbc:mariadb://<host>:<port>/aio_life?sslMode=verify-full'
export FLYWAY_USER='<迁移账号>'
# 通过当前终端或密钥管理系统设置 FLYWAY_PASSWORD
```

私有 CA 可在 JDBC URL 使用 `serverSslCert`。隔离本地测试可明确指定 `sslMode=disable&allowPublicKeyRetrieval=true`；生产连接使用验证证书和主机名的 TLS。使用 JDBC 元数据检查，无需 MySQL 命令行客户端。迁移账号与应用账号区分，按脚本赋予建表、ALTER、数据查询/修改、临时表及存储过程权限。

## 初始化

空库与已有库仅支持 **MySQL 8.x（8.0.16+）**，不再维护 MySQL 5.x 兼容分支和测试。入口禁用 `clean`、自动 baseline、跳过执行和乱序迁移。每次命令带 `compile`，确保 Flyway 加载当前 Java 回调：

```bash
mvn -f tools/flyway/pom.xml compile flyway:migrate flyway:validate
```

Flyway 使用最新 `B`，随后执行更高版本 `V` 并记录 `flyway_schema_history`。同一套文件在 8.0、8.4 上原样执行，不切换目录或运行时改写 SQL；保留并验证全部命名 CHECK，服务端仍执行有效的业务校验。重复执行只处理待迁移版本。新库不创建固定密码管理员；通过注册建立账号，再受控授权。

- 后续变更新增更高版本，例如 `V20261028_07__description.sql`；继续通过 `migrate` 执行。新库仍通过 B 与适用 V 初始化。

`adoption.version=20261028.06` 固定本次接入边界，后续新增 V 时不随最新版本自动提高。隔离测试生成该版本的 `adoption-contract.json`，当前最新结构另用 `schema-contract.json`（8.0）或 `schema-contract-mysql84.json`（8.4）；两者都是新库迁移链的参考结构，不能将其预检通过与历史登记成功混为一谈。117 库现存差异仍会被结构预检报告；`flyway:validate` 通过只表示迁移历史校验通过。

## 日常发布与失败恢复

```bash
mvn -f tools/flyway/pom.xml compile flyway:info
mvn -f tools/flyway/pom.xml compile flyway:migrate flyway:validate
mvn -f tools/flyway/pom.xml compile exec:java \
  -Dexec.args=preflight -Dschema.contract=tools/flyway/target/schema/schema-contract.json
```

上例使用 MySQL 8.0 结构契约；8.4 使用 `schema-contract-mysql84.json`。预检严格比较 CHECK 等全部结构，不提供缺失约束豁免。用户于 2026-10-29 确认服务器已升级至 MySQL 8.x；具体补丁版本及升级后的约束状态仍以实际库预检为准，升级服务器不等于历史结构差异已修复。

检查待执行版本和数据影响，迁移后验证真实结构及受影响功能，再启动依赖新结构的应用。SQL、实体、Mapper、两端调用及当前表结构说明同步维护。已执行 `V` 不改写、删除或重排；修正新增版本，种子继续保留只补缺、不覆盖管理员修改及软删除的语义。

MySQL DDL 隐式提交，失败不等于回滚。停止发布、保持必要停写，核对已生效步骤并按脚本说明恢复；确认后才能处理失败历史并重跑。Flyway `repair` 只修复历史，不修复结构，不用于掩盖已执行文件被改写。没有自动 repair、清空或重建流程。

## 自动验证

```bash
# 纯 Java 单元检查
mvn -f tools/flyway/pom.xml test
# 完整检查：Testcontainers 自建并回收 MySQL 8.0.40 / 8.4.2
mvn -f tools/flyway/pom.xml verify
```

集成测试只使用自行创建的容器、随机数据库和随机密码，不接受业务连接参数。测试覆盖新库、已有库登记、确认历史后的零重跑和数据保留、重复执行、checksum 拦截、CHECK 执行与差异检查、公共字段转换、来源字段补齐、结构对齐及注释迁移的失败恢复。两种 MySQL 均从空库执行交付的冻结 B 和全部 V；测试不改写 CHECK。CI 业务测试也使用同样的两个版本矩阵，全部任务通过才发布镜像。

输出位于 `tools/flyway/target/`：

- `schema/adoption-contract.json`、`adoption-contract-mysql84.json`：隔离 MySQL 8.0、8.4 执行至接入版本后的结构。
- `schema/schema-contract.json`、`schema-contract-mysql84.json`：对应两种 MySQL 执行全部迁移后的当前结构。
- `surefire-reports/`、`failsafe-reports/`：JUnit 验证结果。

v5 契约记录实际版本、表、列、索引、外键、CHECK 和 COMMENT，仅排除基础设施表 `flyway_schema_history`。`sources` 强校验绑定全部迁移 SQL，以及 POM 中 Flyway 插件配置、Flyway/驱动版本和接入版本的规范化摘要（`flyway.settings`）；忽略 XML 排版与注释。`toolSources` 保存完整 POM 和生产 Java 源码摘要，仅用于追溯，不参与有效性判定。因此修改 Java 注释、POM 排版或测试依赖不必重新生成契约；SQL、迁移配置或契约格式变化则必须重新生成。字段语义或结构归一化规则发生不兼容变化时升级格式版本，不靠源码文本变化推断。只接受当前 v5 格式，格式不匹配时重新生成契约。CI 用同一 Maven 工具运行完整迁移测试、上传契约与 JUnit 报告，并通过 `compile flyway:migrate` 初始化业务测试库；迁移测试和业务测试均通过后才发布镜像。

`flyway:validate` 检查文件和执行历史；Java `preflight` 只查询实际结构，归一化整数显示宽度、时间默认语法、DEFAULT_GENERATED 和 InnoDB 外键 NO ACTION/RESTRICT 等等价表达。它不比较业务数据、不修正差异。目标库升级、数据核验、应用发布和客户端验收分别记录。

### 接入与升级回归

`FlywayIT` 为新库和旧库创建独立数据库：旧库停在 `adoption.version`，经预检登记后才执行剩余迁移；新库直接执行全部迁移，最终比较两条路径的实际结构。临时项目追加真实建表迁移的回归复用相同流程，防止测试因“最新结构登记成旧版本”而阻止日常新增 V 迁移。合成未来迁移只存在于临时目录，不进入发布 SQL 或当前契约。

`SeedMigrationIT` 单独验证固定的历史种子区间及 `.06` 修复，检查人工配置、软删除和既有数据保留，不要求未来业务数据迁移永远不改变任何数据。两种 MySQL 版本均覆盖正反两种 ID 冲突的缺失菜单补齐、已有不同 ID/自定义路径名称的菜单保留、软删除不复活、重复执行、无关 ID 冲突失败及修复后重试。

`AdoptionIT` 在 MySQL 8.0/8.4 的有数据异构库验证原生 baseline 只登记历史、全部现有脚本无待执行项、常规 migrate 执行数为 0、结构和数据不变，并验证仅执行后续新增 V。

## 初始化数据约定

- 首页菜单使用 `/`，不生成 `/analytics`。
- `V20261028_06__restore_scheduled_jobs_menu.sql` 修复旧种子的 ID 冲突：新库对象存储保留 `1908`，缺失的定时任务菜单使用 `1912`，仅 Web 管理员可见。若旧库定时任务已占 `1908`，缺失的对象存储菜单用 `1913` 补齐，不改已有菜单 ID 或引用。已有同名或同路径菜单（含软删除、自定义 ID）保持原状；补缺所需的 `1912`/`1913` 被无关菜单占用时失败并人工核对，不静默漏建。
- 菜单 `web_is_enabled`、`mobile_is_enabled` 分别控制 Web 与 Mobile，操作日志仅在 Web 提供入口。
- 初始会员平台预设为 `V20261028_05_010__membership_providers.sql`；后续调整新增迁移，保留管理员修改、停用和逻辑删除状态。
- LLM 会话、消息和模型密钥业务已取消，不初始化对应三张表。
- 文件表 `file_name` 保存完整对象键；普通附件以文件 ID 访问，CBTI 图片使用独立公共入口。
