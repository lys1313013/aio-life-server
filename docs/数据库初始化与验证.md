# 数据库初始化与验证

当前应用只支持 PostgreSQL 18+。结构、种子和后续增量位于 `sql/migrations/postgresql/`；旧 MySQL B/V 文件冻结保留用于原迁移追溯，当前入口不发现或执行它们。

## 新库初始化和后续升级

```bash
export FLYWAY_URL='jdbc:postgresql://127.0.0.1:5432/aio_life'
export FLYWAY_USER='aio_life'
export FLYWAY_PASSWORD='your-password'
mvn -f tools/flyway/pom.xml compile flyway:info flyway:migrate flyway:validate
```

调用方先准备空库及建表权限。初始版本 `20261110.01` 创建当前 72 张业务表、索引、约束与中文注释，`20261110.02` 初始化公共菜单、字典、地区和会员平台，不创建固定密码管理员。之后新增更高版本 V；已在持久环境执行的文件不能改写。仅在用户选定节点生成新 B 基线。

应用通过 `AIO_LIFE_DB_URL`（host:port）、`AIO_LIFE_DB_NAME`、`AIO_LIFE_DB_USERNAME`、`AIO_LIFE_DB_PASSWORD`、`AIO_LIFE_DB_SSLMODE` 连接；不在启动时执行 Flyway。业务连接不含迁移工具。数据库名、用户和密码不得写入公开部署记录。

`info`/`validate` 验证迁移历史，不代表真实结构完全一致。`mvn -f tools/flyway/pom.xml verify` 自动创建隔离 PostgreSQL 18，验证新库、重复迁移、增量数据保留、失败事务回滚和拒绝未知非空库，并生成 v6 PostgreSQL 结构契约。已有 PostgreSQL 首次接入必须执行真实结构预检：

```bash
mvn -f tools/flyway/pom.xml compile exec:java -Dexec.args=preflight -Dschema.contract=/private/path/contract.json
```

只有版本和当前 SQL 摘要匹配、真实结构完全一致时才允许显式 `baseline -Dschema.contract=...`。默认禁用自动 baseline、clean、outOfOrder 和跳过执行。不要使用 repair 掩盖结构差异；失败先查看事务和迁移历史，再新增修复版本。

## 从 MySQL 一次性迁入

使用 `scripts/mysql_to_postgresql.py`；这是离线搬迁工具，不是 MySQL 运行兼容层。安装独立 Python 环境中的 `psycopg[binary]` 和 `pymysql`。凭据只通过环境变量注入，不提交快照、连接信息或真实验证记录。

1. 先执行 PostgreSQL Flyway 初始化，并在隔离 PostgreSQL 完整演练。目标必须与 `sql/postgresql-seed-manifest.json` 逐表摘要完全一致，任何账号、业务数据或修改过的种子均使工具拒绝替换。
2. 确认数据迁移范围，停止旧后端和其他业务写入。原 MySQL 库不删除、不清空。设置 `SOURCE_MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`，执行 `python scripts/mysql_to_postgresql.py snapshot /private/path/new-snapshot`。工具用只读 REPEATABLE READ 一致性快照保存全部表及字段元数据，并逐表记录行数和 SHA-256；输出目录必须不存在且权限为 0700。
3. 设置 `TARGET_PG_DSN` 为 libpq 连接信息，执行 `python scripts/mysql_to_postgresql.py restore /private/path/new-snapshot`。工具在一个目标事务中加锁核对原始种子、替换为当前业务数据、归档源库非日志表及旧字段、重新读取并核对每张当前表与归档摘要；任何错误回滚全部导入，不允许覆盖第二次导入或未知已有库。
4. `public` 只包含当前业务结构及新 PostgreSQL Flyway 账本；运行日志默认不搬迁：`api_key_log`、`login_log`、`mail_log`、`sys_activity_log`、`sys_scheduled_job_log`、`data_export_audit_event` 的目标表保持空；原日志仅留在源库与离线快照。原 MySQL 迁移账本、已取消功能表和备份表在 `migration_archive` 中无损归档，不映射业务实体、不暴露给查询角色。`source_rows.row_data` 为含类型标记的原始整行 JSON 文本，保留二进制、日期和精确小数；不是运行中的旧格式兼容分支。
5. 保留原加密主密钥和对象存储，不修改雪花 ID、用户归属、软删除或审计数据。完成数据核对后切换新后端，验证健康、真实 Mapper 全字段、核心业务查询与 Query 链路。恢复写入以后如需回退，必须先处理新增数据，不直接回切旧 MySQL。

测试不得连接业务库。H2 只承担局部单元测试；PostgreSQL 专属 SQL、并发、事务与约束必须在真实隔离 PostgreSQL 验证。迁移成功和镜像构建成功均不代表运行环境已切换。
