# 数据库初始化与验证

当前应用只支持 PostgreSQL 18+。结构、种子和后续增量位于 `sql/migrations/`；旧库结构、数据和历史修正 SQL 均已从工作树清理，仅在 Git 历史追溯。

## 新库初始化和后续升级

SQL 目录为 `sql/migrations/`，Flyway 按版本顺序执行结构与种子。

```bash
export FLYWAY_URL='jdbc:postgresql://127.0.0.1:5432/aio_life'
export FLYWAY_USER='aio_life'
export FLYWAY_PASSWORD='your-password'
mvn -f tools/flyway/pom.xml compile flyway:info flyway:migrate flyway:validate
```

调用方先准备空库及建表权限。初始结构 `20261110.01` 创建 68 张业务表、索引、约束与中文注释，`20261110.02.001` 至 `20261110.02.011` 分别初始化 CBTI、导出协调记录、荣誉分类、会员平台、银行字典、菜单、日历、系统配置、地区、支付方式和衣柜分类，不创建固定密码管理员。分类文件及顺序见 [SQL 入口](../sql/README.md)。之后新增更高版本 V；日常不改写已在持久环境执行的文件。

> **2026-11-12 迁移链合并**：`V20261111_01` 与 `V20261112_01`–`V20261112_12` 的内容已并入当前基线或公共种子，当前迁移链为基线加 11 个种子及 `V20261112_13` 共 13 个文件，这些旧 V 文件不再存在。已执行过旧链的库不能通过当前链增量升级：`flyway:validate` 会因基线 checksum 变化和已应用版本在本地缺失而失败。必须先按迁移前逻辑备份在新库恢复业务数据（仅数据，不复用旧结构），或按一次性流程对齐历史：先确认结构与当前契约一致，再执行 `flyway:repair` 对齐校验和并标记缺失版本，随后 `flyway:migrate` 应用 `V20261112_13`，最后 `flyway:validate`；不要用 `repair` 掩盖结构差异。2026-11-12 的目标库已按该流程完成对齐，当前版本 `20261112.13`。

应用通过 `AIO_LIFE_DB_URL`（host:port）、`AIO_LIFE_DB_NAME`、`AIO_LIFE_DB_USERNAME`、`AIO_LIFE_DB_PASSWORD`、`AIO_LIFE_DB_SSLMODE` 连接；不在启动时执行 Flyway。业务连接不含迁移工具。数据库名、用户和密码不得写入公开部署记录。

`info`/`validate` 验证迁移历史，不代表真实结构完全一致。`mvn -f tools/flyway/pom.xml verify` 自动创建隔离 PostgreSQL 18，验证新库、重复迁移、增量数据保留、失败事务回滚和拒绝未知非空库，并生成 v6 PostgreSQL 结构契约。已有 PostgreSQL 首次接入必须执行真实结构预检：

```bash
mvn -f tools/flyway/pom.xml compile exec:java -Dexec.args=preflight -Dschema.contract=/private/path/contract.json
```

只有版本和当前 SQL 摘要匹配、真实结构完全一致时才允许显式 `baseline -Dschema.contract=...`。默认禁用自动 baseline、clean、outOfOrder 和跳过执行。不要使用 repair 掩盖结构差异；失败先查看事务和迁移历史，再新增修复版本。

测试不得连接业务库。H2 只承担局部单元测试；PostgreSQL 专属 SQL、并发、事务与约束必须在真实隔离 PostgreSQL 验证。迁移成功和镜像构建成功均不代表运行环境已切换。
