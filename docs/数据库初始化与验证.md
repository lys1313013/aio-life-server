# 数据库初始化与验证

当前应用只支持 PostgreSQL 18+。结构、种子和后续增量位于 `sql/migrations/`；旧库结构、数据和历史修正 SQL 均已从工作树清理，仅在 Git 历史追溯。

## 新库初始化和后续升级

SQL 目录已统一为 `sql/migrations/`，仅移动文件，不修改文件名、版本或 SQL 内容；已有 Flyway 账本无需因目录移动而转换。结构契约绑定迁移路径与工具配置，使用旧路径生成的契约须通过当前修订的 `mvn -f tools/flyway/pom.xml verify` 重新生成。

```bash
export FLYWAY_URL='jdbc:postgresql://127.0.0.1:5432/aio_life'
export FLYWAY_USER='aio_life'
export FLYWAY_PASSWORD='your-password'
mvn -f tools/flyway/pom.xml compile flyway:info flyway:migrate flyway:validate
```

调用方先准备空库及建表权限。初始版本 `20261110.01` 创建 72 张业务表、索引、约束与中文注释，`20261110.02.001` 至 `20261110.02.011` 分别初始化 CBTI、导出协调记录、荣誉分类、会员平台、银行字典、菜单、日历、系统配置、地区、支付方式和衣柜分类，不创建固定密码管理员；`20261112.04` 删除四张无引用的死表后为 68 张业务表；`20261112.05` 只重命名时长与起止列并改写分集 JSON 键，表数量不变。分类文件及顺序见 [SQL 入口](../sql/README.md)。之后新增更高版本 V；日常不改写已在持久环境执行的文件。仅在用户选定节点生成新 B 基线。

应用通过 `AIO_LIFE_DB_URL`（host:port）、`AIO_LIFE_DB_NAME`、`AIO_LIFE_DB_USERNAME`、`AIO_LIFE_DB_PASSWORD`、`AIO_LIFE_DB_SSLMODE` 连接；不在启动时执行 Flyway。业务连接不含迁移工具。数据库名、用户和密码不得写入公开部署记录。

`info`/`validate` 验证迁移历史，不代表真实结构完全一致。`mvn -f tools/flyway/pom.xml verify` 自动创建隔离 PostgreSQL 18，验证新库、重复迁移、增量数据保留、失败事务回滚和拒绝未知非空库，并生成 v6 PostgreSQL 结构契约。已有 PostgreSQL 首次接入必须执行真实结构预检：

```bash
mvn -f tools/flyway/pom.xml compile exec:java -Dexec.args=preflight -Dschema.contract=/private/path/contract.json
```

只有版本和当前 SQL 摘要匹配、真实结构完全一致时才允许显式 `baseline -Dschema.contract=...`。默认禁用自动 baseline、clean、outOfOrder 和跳过执行。不要使用 repair 掩盖结构差异；失败先查看事务和迁移历史，再新增修复版本。

## 已执行旧公共种子的库：一次性拆分登记

本节仅适用于结构版本 `20261110.01` 加旧种子 `20261110.02` 的 PostgreSQL 库。本次分类整理删除旧聚合文件，改为 11 份 `.02.001` 至 `.02.011` 分类迁移，**不使用 `repair`、自动 baseline 或重放种子处理已有库**。新库、只执行过结构 `.01` 的库直接执行正常 `migrate`，无需转换。

1. 保持应用和其他迁移写入停止，备份目标库。先在当前修订运行 `mvn -f tools/flyway/pom.xml verify`，用隔离 PostgreSQL 18 产生 `tools/flyway/target/schema/schema-contract.json`；这是当前结构契约，不是业务库备份。不要使用旧修订契约。
2. 设置目标库的 `FLYWAY_URL`、`FLYWAY_USER`、`FLYWAY_PASSWORD`，执行只读检查：

   ```bash
   mvn -f tools/flyway/pom.xml compile exec:java \
     -Dexec.args=preflight-seed-split \
     -Dschema.contract="$PWD/tools/flyway/target/schema/schema-contract.json"
   ```

3. 检查通过后显式执行一次性登记转换，`seed.split.backup` 指向仓库外、尚不存在的文件，父目录须已存在：

   ```bash
   mvn -f tools/flyway/pom.xml compile exec:java \
     -Dexec.args=adopt-seed-split \
     -Dschema.contract="$PWD/tools/flyway/target/schema/schema-contract.json" \
     -Dseed.split.backup=/private/path/new-seed-history-backup.json
   mvn -f tools/flyway/pom.xml compile flyway:validate flyway:info flyway:migrate
   ```

工具校验 PostgreSQL 版本、真实结构、原结构账本、旧种子成功状态与 Flyway 校验和，并按固定 SHA-256 核对拆分 SQL 可完整还原原种子及顺序。随后以独立事务锁住历史表，备份原账本（文件权限 0600），只将旧 `.02` 登记替换为 11 条分类登记，保留原执行人和执行时间；不执行种子、不读取或更新业务数据。重复转换为无操作；未知、失败、缺失或更高版本的账本会拒绝，事务中失败则回滚账本。不能将此工具用于修复任意迁移校验错误。

原聚合脚本不再保留第二份 SQL；转换证据集中在 `sql/reference/seed-split/seed-split.json`（原 SHA-256、原文件头、分类文件摘要）。原 SQL 可由分类文件的原始片段按序完整还原，也可从清理前 Git 修订追溯。本次只是执行文件分类，实体、表结构及种子清单 `sql/postgresql-seed-manifest.json` 未变化。上述转换工具已在隔离库验证，不代表业务环境已经执行。

测试不得连接业务库。H2 只承担局部单元测试；PostgreSQL 专属 SQL、并发、事务与约束必须在真实隔离 PostgreSQL 验证。迁移成功和镜像构建成功均不代表运行环境已切换。
