# 数据库初始化与验证

只支持 PostgreSQL 18+。独立 Flyway 工具从 `sql/migrations/` 执行，应用通过 `AIO_LIFE_DB_*` 连接数据库。连接信息和凭据从环境变量注入。

## 新库初始化和后续升级

准备空库和建表权限，配置目标连接后执行。

```bash
export FLYWAY_URL='jdbc:postgresql://127.0.0.1:5432/aio_life'
export FLYWAY_USER='aio_life'
export FLYWAY_PASSWORD='your-password'
mvn -f tools/flyway/pom.xml compile flyway:info flyway:migrate flyway:validate
```

空库依次创建 74 张表、导入 14 类公共种子，并执行后续增量。建表脚本和公共种子包含合并前至 `20261120.01` 的结构与公共数据。已有库完成下节的一次性登记后，后续升级复用同一命令。[SQL 清单](../sql/README.md)

## 已有库升级与登记

在合并前已使用旧迁移链的库，需要就 2026-11-20 的整理执行一次 Flyway 历史登记。

1. 在[合并前提交 `e550bc58`](https://github.com/lys1313013/aio-life-server/tree/e550bc58b5b9b3ce06875c496aa16bfd552b2cd5)核对历史，按原链补齐至 `20261120.01`，并用该提交通过 `flyway:validate`。涉及旧附件时先完成下方的[附件四表升级](#附件四表升级)。
2. 备份数据库与 `flyway_schema_history`，确认保留的 15 个版本均已执行，实际结构与合并后的空库等价。
3. 切到合并后的代码，执行一次 `repair`，再校验历史并检查待执行版本。

```bash
mvn -f tools/flyway/pom.xml compile flyway:repair flyway:validate flyway:info '-Dflyway.ignoreMigrationPatterns='
```

此次命令清空默认忽略规则，让 Flyway 一并登记被合并的最高版本 `20261120.01`。修复只同步保留版本的校验和并标记合并版本，实际升级须在步骤 1 完成。

## 结构预检与测试

`mvn -f tools/flyway/pom.xml verify` 使用隔离 PostgreSQL 18，覆盖空库初始化、重复执行、增量数据保留、失败回滚和未知非空库拒绝。业务测试使用隔离库，H2 仅供局部夹具。验证生成的结构契约位于 `tools/flyway/target/schema/schema-contract.json`。

对无 Flyway 历史的非空库，先生成与当前 SQL 来源和目标登记版本匹配的 v6 结构契约，再运行只读预检。确认一致后用相同契约和版本显式执行 `flyway:baseline`。

```bash
mvn -f tools/flyway/pom.xml compile exec:java -Dexec.args=preflight -Dschema.contract=/private/path/contract.json
```

结构差异先用可审计的迁移处理。`info` 与 `validate` 检查迁移历史，结构预检比较数据库中的实际定义。应用启动和镜像构建独立于数据库迁移。

## 附件四表升级

仍停在 `20261116.11` 之前的库应使用合并前代码。停写并备份 PostgreSQL 与对象存储后，先迁移到 `20261116.10`，再运行该提交中的 `tools/attachments/prepare.py --stopped-writes`。工具读取真实对象字节，校验 SHA-256 并准备对象引用及附件 ID。确认迁移前置条件后继续执行旧链，其中 `20261116.12` 回填附件对外 UUIDv4。[原执行步骤及历史异常处理](https://github.com/lys1313013/aio-life-server/blob/e550bc58b5b9b3ce06875c496aa16bfd552b2cd5/docs/数据库初始化与验证.md#附件四表升级)

2026-11-16 至 2026-11-19 的逐版本执行与验收记录可在[合并前文档](https://github.com/lys1313013/aio-life-server/blob/e550bc58b5b9b3ce06875c496aa16bfd552b2cd5/docs/数据库初始化与验证.md)追溯。现行附件模型见[附件与来源表设计](附件与来源表设计.md)。
