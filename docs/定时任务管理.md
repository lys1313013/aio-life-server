# 定时任务管理

适用版本：2026-10-25 新增的轻量调度模块。Web 入口为「系统管理 → 定时任务」(`/system/scheduled-jobs`)，所有接口要求管理员角色，移动端不开启菜单。

## 功能与执行语义

首批注册 `leetcode.check`（打卡检查，默认每天 23:30）和 `leetcode.daily-question`（每日一题通知，默认每天 07:00）。原 `AutoTask` 注解调度已移除，两个入口继续调用现有 LeetCode 业务服务及通知幂等机制。其他内部轮询保持原实现。

- 编辑支持每日时间和六段 Spring Cron；秒只能填写 0～59 的单个整数，最多每分钟执行一次。时区固定为 `Asia/Shanghai`。
- 配置存入 `sys_scheduled_job`，携带 `revision` 做条件更新，冲突需刷新后重试。事务提交后当前实例立即重新调度，其他实例最长约 15 秒同步；旧版本触发回调在执行前再次读取数据库，发现暂停或版本变化时跳过。
- 暂停只取消后续触发，不中断已经开始的业务。暂停任务仍可手动执行一次。
- 总开关 `AIO_LIFE_SCHEDULING_ENABLED=false` 同时关闭本实例的自动和手动执行。多实例部署应统一此设置；否则访问关闭调度的实例会拒绝手动执行。
- 「立即执行」只表示提交到进程内执行器，完成情况查看日志；不提供持久化队列、失败自动重试或停机补跑。请求返回前后进程退出可能导致未执行，操作前应核查日志，不自动重试 POST。
- 专用触发线程 1 个、执行线程 2 个、无等待队列。执行器满时手动请求报忙，自动任务记跳过。同一任务以 Redis/Redisson watchdog 锁互斥；自动执行以 `(job_id, trigger_key)` 数据库唯一键避免同一计划时点被多个实例先后重复执行。
- 互斥不等于业务效果“恰好一次”：Redis 故障、进程崩溃或业务已生效但日志未完成时，结果可能未知。仍依赖现有业务通知的幂等约束，不自动重放。

## 执行日志

`sys_scheduled_job_log` 保存触发方式、计划时间、开始/结束时间、耗时、执行人、结果摘要和实例标识。ID 与 `durationMs` 按后端 Long 契约返回字符串，分页总数返回数字。

| 状态 | 含义 |
|---|---|
| RUNNING | 已获得执行锁，业务正在执行或尚未确认完成 |
| SUCCESS | 业务方法正常返回；不代表所有用户均需要通知，也不代表外部通知已送达 |
| FAILED | 业务方法或执行基础设施异常；业务异常在页面仅显示异常类型，完整堆栈按日志 ID 查服务日志 |
| SKIPPED | 同一任务正在执行或自动执行器已满 |
| INTERRUPTED | 执行锁空闲，但仍有未完成记录；实际业务结果未知 |

每次调度刷新及执行前在同一执行锁内检查遗留 RUNNING，将其标为 INTERRUPTED，保留未知耗时，不推断成功或重试。日志窗口每 5 秒刷新，关闭、离页或请求失败后停止，失败后可手动重试；分页每页 20 条，API 上限 100。当前不提供删除与自动清理日志。

## 接口

| 方法与路径（不含 `/api`） | 用途 |
|---|---|
| `GET /system/scheduled-jobs` | 内置任务列表，包含自动调度状态、时区、版本和按当前规则计算的下次时间 |
| `PUT /system/scheduled-jobs/{id}` | 保存 `{ cron, enabled, revision }`，返回更新后的任务 |
| `POST /system/scheduled-jobs/{id}/run` | 提交一次手动执行；即使任务暂停也可执行，总开关关闭则拒绝 |
| `GET /system/scheduled-jobs/{id}/logs?page=1&pageSize=20` | 执行日志倒序分页 |

新增业务任务须在 `ScheduledJobRegistry` 明确注册并添加默认配置；不可通过页面配置任意 Java 类、方法、Shell 或 SQL。配置和执行日志属于系统运行数据，不纳入个人数据导出。

## 数据库与发布

按[数据库初始化与验证](数据库初始化与验证.md)初始化当前任务与执行日志表、菜单和力扣任务种子。不保留旧版 LeetCode 调度入口；仅配置任务管理中的调度。应用不会自动执行 SQL。
