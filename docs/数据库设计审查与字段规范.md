# 数据库字段规范与待确认事项

当前物理定义、类型、约束和默认值以[建表脚本](../sql/migrations/V20261110_01__postgresql_schema.sql)及后续增量为准，逐表语义见[数据库表结构](数据库表结构.md)。应用与 SQL 的变更规则见 [SQL 脚本规范](SQL脚本规范.md)。

## 待确认事项

| 事项 | 当前约束与下一步 |
| --- | --- |
| 观影和阅读进度 | `movie` 与 `read_record` 用整数表达总进度和当前进度。先定单位及统计口径，再确定评分、日期先后和进度范围；已有值逐项核对。 |
| 目标归属与计划时间 | `year/month/day` 用于日期上下文，`start_date/end_date` 保存计划时刻。跨周期安排及汇总归属需明确后再加约束。 |
| 用户字典业务键 | `user_dict_data` 由 ID 标识。既有记录曾出现空值和重复值，明确各类字典的业务键并预检现有数据后，再决定唯一约束。 |
| 会员平台名称 | `provider_id` 关联平台，保存时复制 `provider`，详情可返回当前 `providerName`。明确自定义名、保存时名称和当前名称的关系后再调整。 |
| 日志保留 | 登录、API、邮件、操作、调度和通知投递按用途定义保留期限及分批清理方式。审计记录单独确定保留期。 |
| 索引与查询 | 候选重叠索引先对比查询计划、访问量和谓词。附件列表按实际查询成本评估批量读取。 |

## 共享字段语义

| 概念 | 当前约定 |
| --- | --- |
| 主键与关联 | 业务主键为 BIGINT `id`，关联列使用 `<对象>_id` 并与被引用键同类型。工作日历以 `calendar_date` 为自然主键。API ID 为字符串，附件对外 ID 为 UUIDv4。 |
| 归属与审计 | `user_id` 记录归属，`create_user/update_user` 记录操作人，`create_time/update_time` 记录持久化时间。`request_time/event_time` 记录各自的业务时点。 |
| 名称与正文 | 对象名称用 `name`，内容标题用 `title`，简要描述用 `description`，正文用 `content`，普通备注用 `remark`。保留评价、学习笔记和加密备注各自的业务语义。 |
| 日期与时刻 | 日粒度用 `DATE`，例如 `event_record.event_date`、`income.income_date` 和观影、阅读的开始与完成日期。具体时刻按本地日期时间契约保存。 |
| 时长与区间 | 名称携带单位，如 `duration_minutes`、`duration_seconds`、`watched_duration_seconds`、`duration_ms`。时迹起止用 0–1439 的分钟数，闭区间计入结束分钟，时长由服务端计算。 |
| 金额 | 区分记账金额、原始交易金额、税前收入、税额、购入价和月均成本。新增字段注明币种、单位及 NULL 和 0 的含义。 |
| 外部身份 | 原平台 ID 使用 `*_id`，业务订单编号使用 `*_no`。不同系统的编号按来源与业务用途维护，API 按字符串传递。 |
| 客户端 IP | 客户端来源用 `client_ip VARCHAR(45)`，可信代理规则由接入层决定。`server_ip` 保存处理请求的实例地址。 |
| 标签 | 目标、荣誉与里程碑的标签为 JSONB 字符串数组。需要复用标签、按标签关联查询时再评估关系表。 |
| 附件 | 对象键、真实 MIME、字节数和摘要由 `storage_object` 维护，`attachment.file_name` 表示下载展示名。业务图片按附件用途和业务 ID 绑定。[附件模型](附件与来源表设计.md) |

### 排序与展示端

普通列表使用 `sort_order`，首页固定列表使用 `pinned_sort_order`。数据库命名用下划线，API 使用 camelCase。数值开关用 `is_enabled`，逻辑删除用 `is_deleted`，多值业务状态用 `status`。系统字典启用状态为 `0/1`，用户字典覆盖项的 `is_enabled = NULL` 表示继承。

`sys_menu.visible_clients` 使用位掩码，1 表示 Web，2 表示移动端，3 表示两端，0 表示均隐藏。访问权限由鉴权规则单独处理。

### 文本比较

普通业务文本使用数据库默认的确定性排序规则。模糊匹配显式用 `ILIKE`，大小写不敏感的精确匹配使用 `lower(col)` 及对应表达式索引。登录、注册查重和找回密码与 `sys_user` 的用户名、邮箱唯一索引使用相同表达式。

路由、键、编码、幂等键和外部标识需要固定字节序时显式使用 `COLLATE "C"`，同义关联列保持一致。需要拼音序时在查询层明确指定排序规则。[SQL 脚本规范](SQL脚本规范.md#2-目录命名与格式)

### 公共预设与用户覆盖

- `time_tracker_category`、`user_dict_data`、`wardrobe_category`、`honor_category` 用 `user_id IS NULL` 表达公共预设。用户行的 `user_id` 为正数，公有预设的审计人可为空。系统参考字典独立维护。
- 支持覆盖的业务用 `template_id` 指向公共项，未填的可继承字段取公共值。接口返回派生的 `preset`。用户可维护本人数据，公共项由系统管理。
- 查询公共项优先使用有效预设部分索引，查询用户项按 `user_id` 过滤。公共预设缓存使用固定键 `preset`。

### 收支与月均成本

| 字段 | 口径 |
| --- | --- |
| `expense.bookkeeping_amount` | 记账金额，计入支出统计。 |
| `expense.transaction_amount` | 原始交易金额，未记录时为 NULL。与记账金额各自更新。 |
| `income.gross_amount` / `tax_amount` | 税前收入与税额。税额 NULL 表示未记录，0 表示零税额。 |
| `device.purchase_price` / `wardrobe_item.purchase_price` | 设备及衣物购入价。 |
| `membership_record.price` / `monthly_amount` | 支付金额与月均成本。用户可填写月均成本，空值才按费用与周期计算。[计算规则](../src/main/java/top/aiolife/membership/service/MembershipRecordWriteService.java) |

## 现行完整性规则

- 衣橱分类删除前检查子分类及关联衣物。系统通知发送人为 NULL，用户消息保存实际发送人。[分类删除](../src/main/java/top/aiolife/wardrobe/service/impl/WardrobeCategoryServiceImpl.java) [建表脚本](../sql/migrations/V20261110_01__postgresql_schema.sql)
- 0/1 状态、支出交易号唯一、银行卡账单日和还款日、银行卡金额及有效期、会员金额及开通到期顺序都有库内约束。卡片类型、业务状态及计费周期的枚举由请求和服务层校验。
- 系统字典项通过 `dict_type_id` 关联类型，标签和值必填且非空白。用户字典保留自己的 `dict_type`，标签 NULL 表示继承，补充属性使用 `extra_data`。
- 登录密码和二级密码使用 bcrypt，API Key 持久化 SHA-256 摘要与展示前缀，第三方访问令牌以 SM4-GCM 密文保存。密码库两端保存明文账号，密码和备注由客户端加密。
- `membership_record.category` 可覆盖平台默认分类。银行卡使用银行字典与自由银行名两种互斥来源。操作日志可保留当时的用户名和昵称，关系表的 `user_id` 可用于隔离查询，写入须验证两端归属。
- `b_video.pages_info`、`episodes`、`current_episode`、`watched_duration_seconds` 分别表示分集元数据、总集数、观看位置和累计时长。足迹的城市名、地区编码和坐标系各有语义，坐标系目前为 GCJ02。导出任务状态和产物状态各自维护。
