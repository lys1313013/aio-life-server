# 视频封面内部存储与历史迁移

## 范围与契约

- 本批只接入视频；物理路径为 system 桶的 bvedio/<完整 SHA-256>.<真实扩展名>。同样字节跨用户只存一份；每个视频保留独立 file 引用，校验属主、当前视频引用、逻辑删除和菜单二次锁。
- b_video.cover 保留原始来源；响应新增 coverFileId、coverState。Web/mobile 只通过带 Authorization 的 /file/preview/{fileId} 读取内部图片，禁止外链/第三方图片代理兜底。旧桶路径预览不能绕过内部图片权限。
- POST /b-video、PUT /b-video/{id}、tagVideo、syncProgress 新建及更新封面均在业务事务中排队。未提供 cover 保持；空串清空；来源不变不重复排队。替换成功前保留旧图。后台更新前锁视频并核对 cover_version。
- GET /b-video/covers?ids=... 批量读取当前用户封面状态，最多100条；POST /b-video/{id}/cover/retry 重试 FAILED 封面。
- 任务最多5次自动尝试，退避重试；最后一次崩溃恢复也会转 FAILED。数据库事务不覆盖网络下载；上传使用共享对象锁并持有到事务完成。物理对象不随业务回滚删除。
- 下载器只允许 hdslb.com 的 /bfs/ HTTPS 图片，旧 HTTP 来源自动升级。禁止 URL 用户名、片段、非标准端口、自动重定向、HTTP 代理；实际连接使用已校验的公网 DNS 地址。系统 DNS 返回代理 Fake-IP 时通过固定 https://dns.google/resolve 查询真实 IPv4，仍校验公网地址及 HTTPS 证书，不放开内网。
- 保留原图字节；按实际图片格式、10MB、1600万像素限制校验。第一版按字节去重，不做相似图合并、来源 URL 永久缓存和自动物理清理。

## 运维操作

1. 核对目标数据库/MinIO，备份 b_video 和 file；备份含用户数据，只能放在受限目录，不能提交。
2. 按 sql/upgrade-plan.json 执行尚未执行的 2026-10-03_video_cover_storage.sql；数据库结构不会在应用启动时自动修改。
3. 用 Java21 编译并生成依赖路径：

```sh
mvn -DskipTests compile dependency:build-classpath -Dmdep.outputFile=artifacts/video-cover-migration/classpath.txt
java -cp "target/classes:$(cat artifacts/video-cover-migration/classpath.txt)" top.aiolife.record.service.VideoCoverMigration
java -cp "target/classes:$(cat artifacts/video-cover-migration/classpath.txt)" top.aiolife.record.service.VideoCoverMigration --apply
```

复用既有 AIO_LIFE_DB_* / MINIO_* / REDIS_* 环境变量，不将密码写进命令行。默认只读；--apply 逐条排队，最多等待20分钟并输出 JSON 报告。只处理未逻辑删除且 cover 非空的视频；READY 跳过，PENDING 恢复，FAILED 重试。重复执行不会重复物理存储。

4. 工具回读全部目标 file 引用及 MinIO 字节，核对 SHA-256、大小、图片类型、用户和业务归属；失败时退出非零，原 cover 保留。报告路径默认 artifacts/video-cover-migration/report.json。
5. 发布/重启匹配后端后再启用新客户端。未更新的后端不会返回新封面字段。客户端页面仅轮询 PENDING，不触发下载；失败可重试。

## 回退

原 cover 未覆盖，旧客户端仍可读取来源。数据库新增结构可以保留；停止新任务并回退应用版本即可。不要直接删除 system 桶或根据某条视频删除图片；回退数据前核对迁移后的业务写入，不能盲目整表恢复覆盖新记录。第一版保守保留已存对象及旧引用，未启用自动清理。
