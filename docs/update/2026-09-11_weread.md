# 微信读书接入

## 范围
记录目录新增一个「微信读书」页面，内含看板、书架、笔记三个 Tab。原有阅读记录保持独立。只读取微信数据，不向微信写入，不做定时同步或历史快照。

## 上线步骤
复用现有 `user_bind`，无需新增表或字段。原独立表建表 SQL 已移除。

1. 执行 `sql/2_ini_data/2026-09-11_weread_menu.sql`（可重复执行）。父菜单采用现有 `Demos` 目录；执行后确认 `/record/weread` 恰有一条有效菜单。
2. 部署前后端；刷新菜单或重新登录。可在「账号绑定 → 微信读书」或「记录 → 微信读书 → 同步设置」输入 Key，两个入口操作同一份绑定。

代码与 SQL 不包含用户提供的真实 Key。

## 接口（均要求登录）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /weread/connection | 是否连接及最近完整同步时间，不返回凭证 |
| POST | /weread/connection | body 为 apiKey；验证后直接保存 |
| POST | /weread/disconnect | 清空当前用户凭证及同步时间 |
| POST | /weread/sync?mode=annually | 读取书架、全部笔记本、周期统计；全部成功后更新同步时间 |
| GET | /weread/stats?mode=monthly | 周期统计 |
| GET | /weread/notes?bookId=... | 单书划线、全部分页想法及书评 |
| GET | /weread/progress?bookId=... | 单书阅读进度 |

mode 支持 weekly/monthly/annually/overall。统一返回 `{rscode:'0',data:...}`；第三方请求失败保持失败语义，不返回伪造的零值。分页游标异常或超过 50 页明确失败，不声称已同步完整。

## 存储
- `user_bind.platform = weread`；用户与平台双重过滤。
- `access_token` 直接保存 Key（不加密），`meta_fields.lastSyncTime` 保存 ISO 格式同步时间，其他扩展字段保留。
- `meta_fields.connectionVersion` 标记每次绑定版本，防止旧同步覆盖新连接的状态。
- 保存新 Key 会清除旧同步时间；留空编辑账号绑定保留旧 Key。
- 两个入口均校验并保存 Key；`includeToken=true` 也不返回微信读书凭证，日志序列化隐藏 token。
- 解绑先清除凭证与同步时间，再逻辑删除该平台绑定，不影响其他平台；再次连接可新增绑定。
- 同一用户的微信读书写入通过用户行锁串行，避免两个入口并发新增重复绑定。

## 数据与安全
- userId 仅取当前登录态，客户端不可指定他人用户。
- 凭证无需额外加密密钥配置；请求 DTO 的 fastjson 与 Jackson 序列化均隐藏凭证。
- 仅访问固定的微信读书 HTTPS 网关以及六个已列出的只读接口；不转发用户提供的 URL。
- 不记录上游错误正文，也不将其回传用户。
- 前端仅内存保存阅读数据，换账号/断开连接时清空；深浅色沿用系统主题。
- 统计日均沿用微信读书自然日口径，已读完数使用周期 readStat；书架未读完不推断为在读。
- 笔记正文采用 Vue 文本插值，外部链接只允许 HTTPS。

### 历史周期查询

- `/weread/stats` 和 `/weread/sync` 接受可选 `baseTime`（Unix 秒，默认 0）。
- 周、月、年查询将 `mode` 与 `baseTime` 传给 `/readdata/detail`，上游归一到周一、月初、年初；累计固定使用 0。
- 前端提供周/月/年日期选择，禁止未来日期；刷新保留所选周期，查询失败保留上一成功周期。
- 无需新增 SQL；每次切换仅调用一次统计接口。
