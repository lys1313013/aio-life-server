# 隐私政策与账号注销

Web 与小程序通过匿名 `GET /auth/legal` 读取同一份隐私政策和服务条款。正文维护在后端资源中，响应带版本、生效日期、运营主体和隐私联系邮箱，不返回其他系统配置；不缓存响应。

## 联系信息与发布准备

当前全量初始化会补缺两项公开配置：`privacy.operator`（实际个人或组织名称）和 `privacy.contact-email`（可收信邮箱）。管理员在系统配置填写，不在代码中虚构运营主体或联系方式。未填写时两端明确显示未配置，不能将此状态当作已完成发布准备。

微信公众平台仍需按实际能力填写并审核《小程序用户隐私保护指引》，覆盖头像、选中的照片与文件、剪贴板等使用情况，并在真机确认平台授权弹窗及拒绝后的行为。客户端自建政策和注册勾选不能代替微信平台声明。小程序政策页提供微信标准指引入口；本次开发不修改公众平台配置。

正文覆盖主动保存的记录、银行卡与身体/地点等敏感信息、第三方账号及凭据、附件、必要日志、本地记住密码、数据权利、未成年人及注销。启用新的第三方服务或改变处理目的时，应同步更新正文和版本，并完成相关告知与授权。

## 注册确认

邮箱注册和微信直接注册都必须主动同意当前版本的隐私政策及服务条款。邮箱注册发送验证码前也先检查勾选。接口分别携带 `agreedPolicy: true` 和 `policyVersion`；服务端不接受未同意、缺失或过期版本，且在消费邮箱验证码/微信票据前检查。

当前版本为 `2026-10-27`，同意版本和上海时区的同意时间写入用户记录。正文与服务端版本必须一起变更，更新两端调用及模拟数据，不保留旧参数兼容分支。

匿名用户可在登录页查看政策，已登录用户在 Web“个人中心 → 隐私与账号”、小程序“我 → 设置”查看。Web 本身没有独立微信注册流程，扫码遇到新微信用户时由同一小程序注册并确认协议。

## 自助注销

- Web：“个人中心 → 隐私与账号”；小程序：“我 → 账号与安全 → 注销账号”。两端先提供导出入口、不可撤销的后果说明，再要求输入“注销账号”并在按钮附近确认。
- 身份复核支持当前登录密码；小程序可用新鲜微信 code，Web 可用微信扫码确认。不接收目标用户 ID，不允许 API Key 或身份切换调用，不绕过菜单锁、密码库主密码或导出授权。
- Web 扫码复用微信登录确认页，但只消费确认后的身份，不签发新登录会话；服务端核对必须是当前账号。扫码本身不会提交注销，仍需回 Web 明确确认。
- `POST /auth/account/close` 受理后立即逻辑停用账号、撤销各设备会话、取消导出及待发通知。客户端仅在受理成功后清除会话和相关缓存，失败保留输入。显示“注销已受理”，不宣称所有数据立即消失。
- `user.erasure_requested_at` 与 `erasure_retry_at` 是持久化任务。受理后先留 5 分钟给在途请求收尾；工作器每分钟扫描到期任务，运行中的导出仍有有效租约时继续等待。失败延后 5 分钟重试；任务不会因重启丢失，日志只记录受控信息。
- 清理包含软删除的个人业务记录、关联明细、用户资料、第三方绑定、API Key、密码库、私人附件、导出文件及启用的 Neo4j 关系图谱。MySQL 用户行锁串行处理同一账号；对象锁覆盖文件引用检查至数据库提交，使用 READ COMMITTED 避免旧快照误删新共享引用。
- 外部资源先做幂等删除，全部成功后事务内清理数据库索引并物理删除用户。外部失败保留资源索引供重试；不把失败吞掉后标为完成。后台应监控错误日志和待清理任务是否积压。
- 公共系统预设、系统卡面及其他用户仍引用的共享图片保留。注销不会删除用户在第三方平台的账号。备份及依法必须保存的信息按实际保存规则处理，政策不承诺所有副本即时删除。

管理员现有“删除用户”仍是停用行为，和本人的不可撤销注销分开。不得通过管理员删除接口替代自助注销的数据清理。

## 验证边界

关键回归使用模拟账号、H2 隔离数据库和模拟外部服务，覆盖协议拒绝、错误身份、重复提交、失败保留、会话撤销、跨用户隔离、软删除记录、共享对象保护与清理重试。这些结果不代表真实 MySQL/Redis/MinIO/Neo4j 的清理联调。

本批暂不提交，不执行提交前全量验证。提交前按各仓库规范集中运行完整检查、H5 E2E、微信构建及包体检查和微信登录专项模拟；查看手机、平板、桌面及深浅主题下的政策长文、注册协议和注销弹窗。必须使用明确可丢弃的隔离账号验证实际注销，不能对真实账号试删。
