# Jev 时迹分类实测报告

日期：2026-09-22。历史记录：本报告使用旧星期方案的输入，结果保持原样。当前测试探针已改用 IWorkCalendarService，下述 6/6 不代表新日历方案的实测表现。

使用真实 TypeSafe API，输入为 6 组虚构时迹，每组调用一次。密钥仅通过运行进程环境传入，报告不包含密钥。

## 结论

- 6/6 个模型首选分类与预先定义的人工预期一致，所有返回都属于提供的真实分类候选，没有未知或空分类。
- 按当前 `confidence >= 0.65` 的规则，4/6 个结果会被采纳；两个周末样例虽然选中预期分类，仍会被标记为低置信度并交给规则兜底。
- 这是 6 组简单构造样例的一次运行结果，不是用户真实行为预测准确率，也未证明优于原有规则。此时不应仅为让这 6 个样例全部被采纳而降低阈值。

## 模型、耗时与用量

- 请求模型：`jev-latest`；实际返回模型：`jev-1.13.0`。
- 6 次 HTTP 调用，无重试；平均 417.3 ms，中位数 318.5 ms，范围 275–948 ms。
- 第一组耗时较长，但当前证据不足以把差异归因于模型冷启动、TLS 或网络。
- 输入 token 总计 5658，输出 token 总计 498，合计 6156；没有查询账单或价格，因此不换算金额。
- JUnit：6 tests、0 failures、0 errors、0 skipped；JUnit 成功表示响应契约有效，分类命中率来自另行比较 `matchesExpected`。

## 如何解读

- 周末样例的不确定性主要体现为早餐尚未结束、睡觉等候选仍有概率：周六运动 0.65、早餐 0.23；周日运动 0.60、早餐 0.22。这里是读取概率分布，不是模型提供的解释。
- 参考日为空时仍选择了运动，概率 0.95、置信度 0.94。这只说明该样例倾向延续今天的运动，不能把高置信度当作对用户下一行为的事实保证。
- 本轮采用“今天 + 上一个同类日”，尚未测试 28 天聚合历史、复杂分类、临时行程改变或真实用户数据；上线前需要独立真实历史回放并与现有规则比较。
- 参考日由本地代码选择，周六测试成功不能解释成 Jev 自己完成了工作日历推断。
- 置信度只是是否采纳的信号，Jev 已经始终输出了分类 ID；低置信度不等于上游返回未知。
