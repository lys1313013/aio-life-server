# 微信小程序登录与注册

本版直接扩展 `user`，不新增身份表。只支持服务端配置的一个微信小程序，业务身份始终为 `user.id`。微信小程序的手机号授权不能直接用于 Web 或 iOS / Android App 微信 OAuth。

## 部署顺序

1. 已有数据库备份后执行一次 `sql/1_init_table/2026-09-30_add_wechat_phone_login.sql`。新数据库直接执行 `2026-08-18_init_all_tables.sql`，不要重复执行增量脚本。MySQL 需支持 CHECK 约束的 8.0.16+。
2. 部署后端，再部署移动端小程序。新实体查询会读取新增字段，不能在迁移前部署后端。
3. 在服务端配置以下环境变量。AppID 与移动端 Git 忽略的本地配置 `src/project.config.json` 中的 `appid` 一致。真实 AppID 不写入移动端源码 manifest 或示例文件；AppSecret 不能放进任何 `VITE_*` 配置或客户端。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AIO_LIFE_WECHAT_MINI_ENABLED` | `false` | 功能开关 |
| `AIO_LIFE_WECHAT_MINI_APP_ID` | 空 | 单个小程序的 AppID |
| `AIO_LIFE_WECHAT_MINI_APP_SECRET` | 空 | 小程序 AppSecret，服务端保管 |

关闭开关或缺少配置时，能力接口返回 `enabled=false`，小程序保留账号密码登录。更换小程序 AppID 涉及用户身份迁移，不能将现有 `wechat_openid` 当作新应用的身份直接使用。

当前小程序使用已验证的微信身份直接注册，不获取手机号，也不依赖手机号权限或付费额度。配置 HTTPS request 合法域名与实际隐私保护指引即可接入此流程。旧版手机号接口仅保留兼容，不由当前客户端调用。

## 数据与约束

- `phone_country_code`：不含 `+` 的国际电话区号，字符串；`phone`：不含国际区号的手机号，字符串。微信 `countryCode` / `purePhoneNumber` 由服务端接收，前端不能自行声明绑定号码。
- 两字段同时为空或同时有效；区号 1–3 位、号码 4–14 位，合计不超过 15 位，不把所有历史用户默认设成 `86`。
- `phone_verified_at`：服务端最近接收可信验证结果的时间，不表示运营商实时核验时间。
- `wechat_openid`、`wechat_unionid` 使用 `ascii_bin`；后者允许为空，不用于自动合并账号。
- `active_flag` 为存储生成列：有效用户为 `1`，已删除用户为 `NULL`。联合唯一索引 `(phone_country_code, phone, active_flag)`、`(wechat_openid, active_flag)` 阻止重复有效凭证，同时允许多次注销后重新注册。
- 微信新用户默认角色为 `user`，用户名为 `u_<雪花ID>`，密码及邮箱为空。普通资料编辑和管理端用户表单不能直接设置微信身份或手机号。
- 沿用原账号密码登录字段；`/user/info` 新增 `accountUsername`（实际用户名）、`hasPassword`、`wechatBound`、`phoneMasked`，不返回完整手机号和微信标识。

## 接口

统一使用 `{ "code": 0, "message": null, "data": ... }`。ID 是字符串，`expiresIn` 是数字秒数。除下表的匿名入口外，其余接口必须使用业务 Bearer Token，临时票据不能访问业务 API。

| 方法 | 路径（含 `/api`） | 鉴权 | 请求 / 用途 |
| --- | --- | --- | --- |
| GET | `/api/auth/wechat/mini/capabilities` | 匿名 | 返回 `{ enabled, registrationEnabled }`，控制小程序登录入口 |
| POST | `/api/auth/wechat/mini/login` | 匿名 | `{ loginCode }`，来自 `uni.login` |
| POST | `/api/auth/wechat/mini/register` | 匿名 | `{ loginTicket }`，明确注册新账号，无需手机号 |
| POST | `/api/auth/wechat/mini/phone-login` | 匿名 | `{ loginTicket, phoneCode }`，后者来自用户主动手机号授权 |
| POST | `/api/auth/wechat/mini/bind` | 业务 Token + 原密码 | `{ loginTicket, password }`，绑定到当前账号，不接受客户端 userId |
| POST | `/api/auth/wechat/mini/password` | 业务 Token + 新鲜微信凭证 | `{ loginCode, newPassword }`，仅首次设密，8–128 位 |

`/login` 已匹配到 `wechat_openid` 时直接登录，不重复调用手机号授权。未绑定时返回：

```json
{
  "code": 0,
  "message": null,
  "data": {
    "status": "PHONE_REQUIRED",
    "loginTicket": "服务端生成的随机一次性票据",
    "expiresIn": 300
  }
}
```

`PHONE_REQUIRED` 为兼容旧客户端保留的状态名，含义为“微信身份未绑定账号”，当前客户端不再请求手机号。用户选择“注册新账号”调用 `/register`，或选择“已有账号，登录并绑定”。首次注册必须是明确操作，不在 `/login` 静默创建账号。

`/register` 原子消费五分钟的微信身份票据，以服务端验证的 openid 创建普通用户；手机号、区号和手机号验证时间均为空。票据重复使用或携带手机号的原账号绑定票据均被拒绝。同一微信已注册时返回原账号，并发冲突由唯一索引保护。新客户端仅在 `registrationEnabled=true` 时展示此入口，旧后端仍提供普通账号注册与绑定入口。

`/phone-login` 完成微信手机号验证后：

- 号码尚未占用：在短事务中创建用户，然后签发 Sa-Token。
- 号码已属于其他有效用户：返回 `status=BIND_REQUIRED` 和新的票据，前端要求原账号密码。绝不仅凭相同手机号自动合并或接管原账号。
- 微信与手机号指向不同账号：返回 HTTP 409 及结构化业务错误，不覆盖任何已有绑定。

成功登录响应继承原 `UserLoginVO` 字段，并增加以下字段：

```json
{
  "code": 0,
  "message": null,
  "data": {
    "status": "LOGGED_IN",
    "id": "1234567890123456789",
    "accessToken": "业务Token",
    "realName": "生活记录者",
    "username": "生活记录者",
    "roles": ["user"],
    "accountUsername": "u_1234567890123456789",
    "newUser": true,
    "hasPassword": false
  }
}
```

`username` 保持旧接口的展示字段语义，实际账号使用 `accountUsername`。未设置密码时，小程序提供首次设密及跳过入口；以后微信登录仍可进入设密步骤。首次设密要求新微信凭证对应当前账号，不能覆盖已有密码。

老账号绑定先调用已有 `/api/auth/login` 验证用户名和密码，再携带该 Token 调用 `/bind`，后端再次验证原密码。移动端只保存最终会话，并尽力注销原账号验证产生的临时会话。已绑定其他微信、手机号属于其他账号或与本账号号码不同，均拒绝覆盖；本版不提供自动换绑和数据合并。

## 一次性凭证、并发与失败处理

- `loginCode` 与 `phoneCode` 用途不同，不能混用。只在后端调用微信接口；不接受前端传来的 openid、unionid 或手机号作为身份凭证。
- 登录票据为 32 字节安全随机数，在 Redis 按 AppID 隔离存放，5 分钟过期。原子 GETDEL 消费，重复提交只能成功一次；票据、code 均不落客户端持久化存储。
- 手机号匹配旧账号的第二阶段票据只能用于绑定，不能再次用于注册。失败或超时后重新发起微信登录；取消原生授权尚未请求后端时可在票据有效期内重试。
- 应用级 access_token 按 AppID 缓存，提前 60 秒过期，使用现有 Redisson 锁刷新；session_key 不保存、不返回。
- 微信 HTTP 连接超时 3 秒、读取超时 5 秒。请求可能已消费 code，手机号接口不会盲目自动重放；上游异常只返回固定业务提示。
- 登录按来源 IP 每分钟 30 次，其余微信凭证操作每分钟 10 次。来源使用 `request.getRemoteAddr()`；反向代理部署应正确配置可信代理解析，不能直接信任任意客户端 X-Forwarded-For。
- 外部微信请求在数据库事务外；账号创建/绑定在短事务内，唯一索引处理并发竞争，提交后才签发会话。
- API Key 不允许执行微信绑定或首次设密。通用请求日志对整个微信认证 Controller 隐藏参数，不记录 code、票据或密码。

## 微信开发者工具联调与故障定位

开发者工具可以调用真实 `wx.login`，使用与后端一致的 AppID，向实际后端提交新获取的 `loginCode`。`capabilities.enabled=true` 只表示开关开启且配置非空，不代表微信凭证交换已经验证通过。

1. 在 Network 查看 `/api/auth/wechat/mini/login`：`PHONE_REQUIRED` 表示微信身份验证成功，下一步选择手机号注册或已有账号绑定；`LOGGED_IN` 表示已绑定账号登录成功。
2. 已有账号选择“已有账号，登录并绑定”，验证原密码后完成绑定；退出再点微信登录，应直接回到同一账号。这条路径不调用手机号接口。
3. 手机号注册需要单独验证微信平台权限、额度与用户主动授权；开发者工具登录通过后，仍需真机验收授权、退出和再次登录。
4. 前端的“服务暂时不可用，请稍后重试”是 HTTP 5xx 的通用提示。排查时读取实际 HTTP 状态及响应 `message`，不要把它当作微信原始错误。

2026-10-02 复现的 HTTP 502：微信 `code2Session` 实际返回 `Content-Type: text/plain`，正文是 JSON；直接使用 `body(JsonNode.class)` 会因没有匹配的转换器而失败。微信客户端统一先读取字符串再解析 JSON，覆盖身份、应用 Token 和手机号三个接口。回归测试同时覆盖 `application/json`、`text/plain` 及非 JSON 正文。诊断日志只记录接口阶段、数字 `errcode` 或异常类型，不输出请求 URL、响应正文、AppSecret、code、openid 或 Token。

本次修复验收：23 项客户端、业务、日志与密码兼容测试通过；Java 21 打包通过。线上部署修复后，开发者工具真实 `wx.login` 与登录按钮均完成身份验证并进入账号注册/绑定选择，接口返回 HTTP 200、`code=0`、`status=PHONE_REQUIRED`。首次账号绑定、手机号注册和真机验收需要分别完成，不能以该状态宣称整个登录流程通过。

本次线上临时修复镜像为 `aio-life-server:wechat-json-20261002`，在 `/opt/soft/aio-life` 使用 `docker-compose -f docker-compose.yml -f compose.wechat-json-fix.yml up -d --no-deps backend` 启动；旧镜像保留为 `aio-life-server:before-wechat-json-20261002`。后续正式发布必须包含本次源码修复，再切回常规镜像部署；单独使用原 Compose 文件会覆盖临时修复版本。

## Web 通过小程序扫码确认登录

Web 登录页根据 `GET /auth/wechat/web/capabilities` 的 `enabled` 展示扫码入口。
网页调用 `POST /auth/wechat/web/create`，取得小程序码、随机 `scene`、独立 `browserSecret` 和 300 秒有效期。
二维码只含 32 位随机场景值，指向 `pages/auth/web-login`；浏览器密钥只保存在页面内存，通过 JSON 请求体查询状态和兑换，不能放入二维码、URL、日志或持久化存储。

流程：微信扫码 → 小程序登录/无手机号注册/绑定原账号 → 返回确认页 → 用户明确确认 → 原浏览器兑换一次性凭证 → 复用 `LoginSessionService` 和 Web 用户/权限初始化。
小程序确认时重新取得 `wx.login` code，服务端核对其 OpenID 与当前会话账号一致；API Key 不可用于扫码、确认或取消。页面展示当前账号，禁止仅扫码就登录网页。

接口均在 `/auth/wechat/web` 下：

| 方法/路径 | 身份与输入 | 作用 |
| --- | --- | --- |
| GET `/capabilities` | 匿名 | 是否开放入口 |
| POST `/create` | 匿名；每 IP 每分钟 10 次、全局每分钟 100 次 | 请求微信小程序码并创建登录请求 |
| POST `/status` | `scene + browserSecret` | 查询 WAITING / SCANNED / CONFIRMED / CANCELLED / CONSUMED / EXPIRED |
| POST `/exchange` | `scene + browserSecret` | 确认后一次性签发 Web 会话 |
| POST `/revoke` | `scene + browserSecret` | 网页离开或刷新时撤销请求 |
| POST `/scan` | 业务会话 + `scene` | 认领二维码，锁定当前账号 |
| POST `/confirm` | 业务会话 + `scene + loginCode` | 核验当前微信身份后确认 |
| POST `/cancel` | 业务会话 + `scene` | 用户取消 |

Redis Lua 原子处理状态迁移，保存密钥摘要，扫码与轮询不会延长 TTL；取消、过期、已消费不能再次登录。不同扫码账号不能覆盖原认领账号，兑换时重新读取账号排除已删除用户。响应设置 `Cache-Control: no-store`。网络中断造成兑换结果不确定时，前端要求重新扫码，不自动重放。

### 发布顺序

1. 部署包含上述接口的后端，`AIO_LIFE_WECHAT_WEB_SCAN_ENABLED=false`（默认）。微信小程序配置继续使用现有 AppID/AppSecret，不需要网站应用 AppID，也不需要手机号权限。
2. 上传并发布包含 `pages/auth/web-login` 的小程序；测试环境可将 `AIO_LIFE_WECHAT_WEB_SCAN_ENV_VERSION` 设为 `trial` 或 `develop`，相应微信账号需有该版本的访问权限。
3. 部署 Web，再设置 `AIO_LIFE_WECHAT_WEB_SCAN_ENABLED=true`，正式环境 `AIO_LIFE_WECHAT_WEB_SCAN_ENV_VERSION=release`。正式版取码检查页面存在，未发布不能直接开启。
4. 用微信真机扫描网页小程序码，分别验证已有用户、新用户注册、取消、过期刷新及网页成功进入原账号。微信获取 access_token 的服务器 IP 白名单等要求沿用现有微信后台配置。

新增环境变量由 `application.yml` 读取；根仓库 Compose 使用 `env_file: .env`，修改环境变量后需重建后端容器。
