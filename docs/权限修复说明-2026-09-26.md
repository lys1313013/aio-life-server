# 接口权限修复说明

## 范围与状态

本次实现用户指定的七类权限修复。原审计报告保留原结论；本文件记录代码变更，不将静态审阅等同于运行复现或部署成功。没有修改数据库、调用线上服务、发送通知或提交/推送代码。

| 范围 | 修复行为 |
|---|---|
| 分类与字典 | 普通私有记录更新固定原 owner、templateId 和创建字段，数据库 UPDATE 同时限定 id、userId。公共模板仍走既有管理员入口；普通用户对公共模板的个人覆盖机制保留。 |
| 想法关联事件 | 新事件仅接受业务内容并生成 ID；已有事件仅按 id + 已授权 thoughtId 更新，不再执行不受原父记录约束的 upsert。父子更新置于同一事务，拒绝外来事件时回滚父记录变更。 |
| 任务、列、明细排序及演出 | 排序仅写排序字段（任务可写原有 columnId）；客户端 owner、内容和审计字段不进入排序更新。明细及演出更新固定 owner，同时保留 WHERE owner 条件。 |
| 荣誉与演出附件 | 业务记录更新未命中时立即拒绝；仅更新成功后绑定附件，业务更新与绑定共用事务。文件本身继续由文件服务校验上传者。 |
| 二级锁 | 菜单到 API/MCP 的显式映射、数据库父子菜单展开、全部相关锁检查，以及 MVC 解码路径匹配；工具授权在请求身份上下文内执行。 |
| 时迹与衣柜分类 | 写入检查关联分类归属，名称回填仅查询本人/公共分类；历史停用分类仍可展示，但不会查询他人的私有分类。 |
| 力扣通知 | 手动全局通知入口增加 admin 角色要求，原有定时任务与收件人偏好、日期去重保持原业务语义。 |

## 二级锁兼容与维护

- `SecondaryLockPolicy` 集中维护菜单、REST 前缀、旧菜单路径别名和 15 个 MCP 工具的业务映射。新增工具未映射时拒绝调用，维护者需要同步登记业务菜单。
- `SecondaryLockMenuCache` 按 `sys_menu.parent_id` 展开父菜单，保存“原锁定菜单路径 → 受保护菜单”的关系。缓存保留 60 秒有效期，用户保存锁配置时主动失效。
- 请求路径取 Spring MVC 解析后的路径段，使用 `valueToMatch` 处理编码和矩阵参数，避免原始 URI 与路由语义不一致。
- 父子锁同时配置时全部检查。验证一次二级密码会解锁目标菜单及其对应父级锁，Redis key 仍使用原锁定路径。
- REST 的 `2001` 响应携带 `data.menuPath`。前端接口错误使用真实锁定路径，解锁成功后保留当前页面，不把 API URL 当作页面跳转；路由守卫触发的解锁仍正常跳转。
- 解锁不会自动重放先前失败的请求，尤其不会自动重发写操作；用户需重新操作或刷新数据。
- 仪表盘卡片及 `dashboard_cards` 检查涉及业务锁。聚合工具要求相关数据全部可访问，不返回部分受锁数据。
- 私有文件按文件业务类型检查当前用户的业务锁，公开文件保留公开读取语义。
- 时迹读取运动明细时检查运动锁；写入阅读/电影关联状态前检查相应锁。时迹修改/删除只有存在关联运动时才检查运动锁，新增运动也需解锁。
- 字典配置与统计聚合可能对应多个菜单；存在多个相关锁时须全部满足。
