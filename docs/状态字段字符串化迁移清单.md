# 状态字段字符串化迁移清单

> 目标：将数值型（tinyint/int/char(1)）的状态/类型枚举字段统一迁移为 **小写蛇形字符串**（`varchar`），提升可读性与 AI 友好度。
>
> 统一规范：
> - 值风格：**lower_snake_case**（如 `in_progress`）
> - 列类型：`varchar(16)` ~ `varchar(32)`，不使用 MySQL 原生 `ENUM`（加值要 DDL）
> - Java 侧每个字段对应一个枚举类，写库路径必须走枚举，禁止散落字符串字面量
> - 已有字符串语义化字段中，`milestone.type`、`membership_record.category` 等小写风格即本规范的目标风格

## 一、应迁移（数值型多值枚举）

## 三、需规范化（已是字符串但无约束）

| 表 | 字段 | 问题 |
|---|---|---|
| `device` | `status` | `varchar(255)` 过长且无枚举说明，应收窄为 `varchar(32)` 并定义取值（如 `in_use/idle/retired/sold`） |
| `expense` | `transaction_status` | 来自第三方账单导入，值不受控；建议保留原值列，另加规范化后的语义列或在导入层映射 |

## 四、纯布尔字段，建议保持 0/1 不动

布尔语义只有两态且无扩展预期，迁移无收益：

`is_deleted`、`is_read`、`is_default`、`is_top`、`is_public`、`is_completed`、`is_enabled`、`enabled`、`favorite`、`hidden_content`、`is_pinned`、`is_starred`、`auto_renew`、`is_manual`、`is_track_time`、`is_special`、`is_readonly`、`user_quick_nav.enabled`

> 例外讨论点：`task_detail.is_completed` 若未来要支持"进行中"状态，应直接改为 `status` 字符串字段；当前无此需求则不动。

## 五、迁移执行要点

1. **每张表三步走**：`ALTER TABLE` 改列类型 → 一次性 `UPDATE` 映射旧值 → Java 实体改枚举 + 全局排查 SQL/XML 中的数字字面量
2. **迁移 SQL 模板**（以 `goal.status` 为例）：

   ```sql
   ALTER TABLE goal MODIFY COLUMN status varchar(16) NULL COMMENT '目标状态：not_started/in_progress/completed/abandoned';
   UPDATE goal SET status = CASE status
       WHEN '0' THEN 'not_started'
       WHEN '1' THEN 'in_progress'
       WHEN '2' THEN 'completed'
       WHEN '3' THEN 'abandoned'
   END;
   ```

3. **先代码后 DDL 的坑**：`tinyint → varchar` 直接改列时 MySQL 会把 `1` 变成字符串 `'1'`，CASE 映射要用字符串比较
4. **前端联动**：前端若有 `status === 1` 之类的判断需同步改；接口响应中 status 值变化属破坏性变更，前后端要同版本发布
5. **`b_video.status` 前置工作**：文档未记录取值含义，需先查 `b_video` 相关代码（syncProgress 同步逻辑）确认现有值的语义，再定目标枚举
6. **大写转小写很简单**：`UPDATE feedback SET status = LOWER(status);` 即可，但 Java 枚举和前端常量要同步
7. **建议分批**：P0 一批（改动面最大，含前端）、P1 一批（纯后台）、大写转小写 + P2 一批
