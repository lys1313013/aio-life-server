# SQL 脚本规范

适用范围：本仓库新增或修改的全量建表、增量迁移与数据初始化脚本。结构变更必须同时维护全量和增量；此前清理历史脚本不取消后续增量维护。执行流程见[数据库初始化与验证](数据库初始化与验证.md)，当前结构见[数据库表结构](数据库表结构.md)。

117 数据库实际运行 MySQL 5.7.44（2026-10-22 核验，版本字符串为 `5.7.44-log`）；CI 使用 MySQL 8.0。执行前必须核对目标库实际版本，在文件头声明并验证该脚本的兼容范围，不能直接假定目标库为 8.x。依赖 CHECK 约束生效时，最低版本为 8.0.16；5.7 不能提供该约束保障。单份脚本在 5.7 上验证通过，不代表全量初始化、初始化种子数据或应用所有功能均兼容 5.7。

## 1. 强制要求

- **每张业务表必须有中文表注释，每个字段必须有中文字段注释。** `id`、用户归属、版本、审计字段、逻辑删除字段也不能省略。
- 表和字段使用数据库可保存的 `COMMENT`，不能只在 SQL 上方写 `--` 或只写 Java 注释。
- 索引和约束必须在定义前使用 `--` 说明业务用途或保护的规则；复合索引说明对应查询条件、排序或唯一范围。索引可额外使用 `COMMENT`；CHECK、外键不添加 MySQL 不支持的 COMMENT 语法。
- 新增或修改枚举、布尔、金额、日期、坐标等字段，必须说明取值、单位或特殊语义。默认值、NULL、空字符串、0 的含义不能含糊。
- 注释、实际 SQL、接口校验和业务实现必须一致；禁止保留已经失效的说明。
- 不提交凭据、真实用户数据、生产地址或无关演示数据。

缺少表注释、字段注释或索引/约束说明的新增 SQL，视为未完成，不进入交付。

## 2. 目录、命名与格式

| 内容 | 目录或入口 | 要求 |
| --- | --- | --- |
| 新库最终结构 | `sql/1_init_table/2026-08-18_init_all_tables.sql` | 表示当前完整结构，新库不重复执行历史 ALTER |
| 已有库增量升级 | `sql/migrations/YYYY-MM-DD_NN_description.sql` | 按日期和同日序号排序，声明适用结构与依赖；新库不重复执行已包含的变更 |
| 初始化数据 | `sql/2_ini_data/` | 保留当前默认数据及明确的重跑语义 |
| 菜单初始化 | `sql/menu/2_ini_data/` | 先基础菜单，再按日期执行补缺种子 |
| 结构与发布说明 | `docs/数据库表结构.md`、`docs/数据库初始化与验证.md` | 同步最终结构、特殊值及初始化顺序 |

- 使用 UTF-8；SQL 关键字与类型使用大写，表名、列名使用英文小写下划线并加反引号。
- 每个字段、索引、约束单独占行，缩进统一为两个空格，语句以分号结束。
- 表使用项目统一的 InnoDB、`utf8mb4` 和 `utf8mb4_unicode_ci`；字段排序规则存在业务例外时说明原因。
- 索引使用 `idx_<table>_<purpose>`，唯一索引使用 `uk_<table>_<purpose>`，CHECK 使用 `ck_<table>_<rule>`；已有名称不为统一格式而无故重命名。
- 种子数据由调用方选择目标库，不使用跨库限定表名。验证器仅剥除约定的 aio_life 初始化库指令，拒绝其他跨库操作。

## 3. 文件头必须说明执行条件

每份新增脚本都包含以下信息。对建表或纯注释脚本，也要明确“不回填数据”或“仅修改元数据”。

```sql
-- 目的：初始化当前业务所需默认数据。
-- 前置：已执行当前全量结构；数据库版本符合本文件要求。
-- 影响：只补缺失数据，不覆盖管理员配置。
-- 重跑：可重复执行，不恢复软删除项。
-- 执行：由调用方指定目标库，遇错停止。
```

## 4. 注释写什么

注释表达字段的业务含义，不重复字段类型，不使用“字段”“数据”“信息”等没有具体含义的文字。

| 字段类别 | 必须说明 | 示例 |
| --- | --- | --- |
| 主键 | 标识对象、生成方式 | `足迹ID，由应用生成雪花ID` |
| 用户归属/引用 | 所属对象或引用对象 | `所属用户ID，用于用户数据隔离` |
| 版本 | 初始值和递增规则 | `乐观锁版本号，从1开始，每次编辑递增` |
| 状态/布尔/枚举 | 全部有效值及含义 | `逻辑删除标记：0=未删除，1=已删除` |
| 日期/时间 | 业务时点、精度、特殊值；涉及时区时注明约定 | `结束日期，9999-12-31表示至今` |
| 金额/数量 | 单位、零值和 NULL 含义 | `余额，单位元；NULL表示未记录，0表示零余额` |
| 经纬度 | 经度或纬度、坐标系、单位 | `经度，GCJ02坐标，单位度` |
| 第三方标识 | 供应商、用途、为空的情况 | `百度地点UID，手动选点或未获取时为空` |
| 可空业务字段 | NULL 的业务含义 | `详细地址，可补充楼栋和房号，未填写时为空` |
| 审计字段 | 记录的是谁或什么时间 | `最后更新人用户ID，未记录时为空` |

通用主键、审计字段等简单字段使用简短注释即可。存在特殊规则时必须写清，不能为了简短省掉特殊值或单位。

```sql
-- 按用户和删除状态筛选，并按开始日期排序读取足迹。
KEY `idx_footprint_user_start` (`user_id`, `is_deleted`, `start_date`),
-- 结束日期不得早于开始日期；9999-12-31 表示至今。
CONSTRAINT `ck_footprint_end` CHECK (`end_date` >= `start_date`)
```

## 5. 字段与约束设计

- ID 使用 BIGINT，与现有雪花 ID 和实体映射一致；API 按项目约定输出字符串。
- 精确到日使用 DATE，日期时间使用项目既有 DATETIME 约定；不为方便展示而保存日期字符串。
- 金额和需要固定精度的坐标使用 DECIMAL，明确精度及单位。金额字段与接口的序列化遵循对应业务契约。
- 必填字段明确 NOT NULL。不要为了迁移成功而盲目添加 0、空字符串或某个日期作为默认值。
- 特殊值必须在表注释/字段注释、实体、接口、展示和校验中保持一致。例如生活足迹只用 `end_date = '9999-12-31'` 表示至今，不再同时保存 `ongoing`，界面显示“至今”。
- CHECK、唯一索引和外键按实际业务设计，约束名可定位问题。业务不要求唯一的组合不能擅自添加唯一约束。
- CHECK 不能替代 NOT NULL；判断结果为 NULL 的表达式不能被当作必填校验。
- 索引依据实际过滤、关联、排序设计；说明复合索引顺序和唯一键对逻辑删除的处理，不能简单把 `is_deleted` 加入所有唯一索引。
- 沿用 `is_deleted` 和 BaseEntity 审计字段。没有真实需求时，不新增幂等键、冗余状态或其他控制字段。

## 6. 结构修改、增量升级与初始化

- 每次新增、修改或删除表、字段、索引和约束，都必须同步更新当前全量结构，并提供已有库可执行的增量脚本；不能以尚未上线或曾清理历史脚本为由省略增量。
- 增量脚本在文件头声明目标 MySQL 版本、适用的变更前结构、依赖顺序、数据影响、必要回填、重跑策略与验证方式。需要回填时按业务规则保留现有数据，不伪造默认值。
- 明确哪些步骤只能执行一次；可重跑脚本须检查实际结构，不能把任意 SQL 错误吞掉后视为成功。MySQL DDL 可能隐式提交，须说明部分执行失败后的恢复步骤。
- 增量用于把已有库升级到当前结构；应用不因此保留旧字段双写、旧接口或旧客户端兼容分支。已清理的历史脚本不要求重新恢复，后续新增增量须保留以供尚未升级的环境执行。
- `CREATE TABLE IF NOT EXISTS` 不会更新已有表；全量初始化仅用于空库，不把重跑当作开发库升级。
- 结构修改同步实体、Mapper、当前请求/响应、两端调用与表结构文档。
- 初始化脚本说明重跑策略。补缺操作不得覆盖管理员配置、用户修改或软删除状态；这是当前初始化与日常维护语义。
- 不自动清空或重建既有开发库；本任务没有数据库操作授权时，只修改仓库中的全量与增量脚本。

## 7. 同步与验收

提交前逐项检查：

1. 每张新增表和每个新增/修改字段均有非空、准确的 COMMENT，通用字段无例外。
2. 索引、约束的用途有说明，注释与 NULL、默认值、枚举和特殊值一致。
3. 当前全量结构、增量执行后的结构、实体和结构文档一致；交付说明列出本次增量脚本与执行顺序。
4. 结构变更同步实体、Mapper、请求/响应和客户端；新增业务表按后端规范通过真实 MySQL 全字段查询。
5. 根据变更范围分别验证空库初始化，以及从声明的变更前结构执行增量后的结果、既有数据保留、错误路径和声明支持的重跑行为。现有初始化 CI 不等于增量验证通过。不能拿 H2 结果代替 MySQL 专属 DDL 验证。
6. 纯文档、SQL 行注释或数据库 COMMENT 调整，检查差异、引用、脚本语法及列属性保持；不默认运行全量业务测试或客户端构建。尚未执行实际 SQL 时明确说明。
7. 当前结构校验器不比较注释，结构对比通过不代表注释完整。审查源文件；实际执行结构后，可用 `SHOW CREATE TABLE` 或 `information_schema.columns.COLUMN_COMMENT` 核对。

本规范适用于后续新增和修改的 SQL。历史全库注释缺失另行安排修正，不因编写规范就自动改动全部表或部署数据库。
