# 操作和访问日志

系统管理新增两个管理员菜单：`/system/operation-log`、`/system/access-log`。页面提供日期范围（默认最近 8 个自然日）、用户账号模糊查询、重置、分页和导出全部。清空日期可查询全部时间；重置恢复默认范围。导出使用已查询的筛选条件，不受当前分页限制，文件为带 UTF-8 BOM 的 CSV。

## 上线顺序

1. 新版服务启动前执行 `sql/1_init_table/2026-09-22_add_sys_activity_log.sql`，创建日志表并迁移旧 `login_log` 的非敏感字段。
2. 执行 `sql/2_ini_data/2026-09-22_activity_log_menus.sql`，添加管理员菜单。菜单脚本可重复执行；历史回填按旧 ID 去重，但应仅在切换新版服务前执行，避免将新版双写的登录事件再次导入。
3. 部署后端和前端，重新登录以刷新动态菜单。

此变更不会自动执行 SQL 或修改远程数据库。

## 采集范围

- 访问日志：`/auth/login` 的成功/失败及 `/auth/logout` 的登出。登出前保存用户 ID；历史登录记录的浏览器显示“未知”，不补造历史登出事件。
- 操作日志：通过鉴权并进入 Controller 的已登录请求，包含查询和写入。排除会话信息、权限码、未读消息心跳、文件预览及下载。认证拦截器拒绝的请求、定时任务和直接调用 Service 的 MCP 操作不在此范围。
- 功能名称根据 `X-Page-Path` 匹配数据库菜单（最多缓存 60 秒），功能项根据请求方法及处理方法识别为查询、修改、新增、删除、导出、提交。无页面来源的客户端显示“接口操作”。页面来源只是显示上下文，不用于权限判断。
- 用户账号和名称从用户表查询并保存快照，登录失败仅保存尝试的账号；浏览器从 User-Agent 解析。
- IP 使用 Servlet 的 remoteAddr，若部署在反向代理后，需由部署侧已信任的代理地址解析配置提供真实来源；不直接信任任意 X-Forwarded-For。
- 结果按 `ApiResponse.rscode == '0'` 或抛出的异常判定。日志独立事务写入；写入失败记录服务端错误，不覆盖业务响应。
- 不保存请求参数、密码、Token、响应正文或异常内容；原有 `login_log` 写入逻辑保持现状，新接口只查询新表。

## 接口

仅 `admin` 可调用：

- `GET /api/system/logs/operation`
- `GET /api/system/logs/access`
- `GET /api/system/logs/operation/export`
- `GET /api/system/logs/access/export`

查询参数：`startDate=2026-09-15&endDate=2026-09-22&username=001&page=1&pageSize=20`。起止日期可独立省略，结束日期包含整天；page 最小 1，pageSize 为 1–100。列表按操作时间、ID 倒序，返回 `{rscode:'0',data:{items:[],total:0}}`，ID 按系统规则序列化为字符串。

导出按 ID 倒序，每批 1000 行，以开始导出时的最大 ID 为上界，不将整个结果集载入服务端内存。CSV 对公式前缀进行转义。没有删除或修改日志的接口。
