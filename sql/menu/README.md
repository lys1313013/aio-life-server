# 菜单 SQL

菜单专属 SQL 统一放在本目录，新增菜单入口或菜单结构迁移也放到这里。

| 目录 | 内容 |
|---|---|
| `1_init_table/` | 菜单图标颜色、分端启停、用户隐藏菜单等结构迁移 |
| `2_ini_data/2_menu.sql` | 基础菜单初始化，包含顶级目录 |
| `2_ini_data/202*.sql` | 微信读书、日志、银行卡卡面、对象存储、会员平台、身体数据、生活足迹、定时任务等菜单补缺脚本 |

## 新库

1. 执行 `../1_init_table/2026-08-18_init_all_tables.sql`，其中保留完整菜单表结构。
2. 执行 `2_ini_data/2_menu.sql`，先建立父菜单。
3. 执行 `../2_ini_data/*.sql` 的业务数据，再按文件名顺序执行 `2_ini_data/202*.sql` 的菜单补缺脚本。

新库不要再执行本目录 `1_init_table/` 的历史结构迁移。完整命令与 CI 使用同一顺序，见 [项目 README](../../README.md)。

## 旧库

按照 [升级计划](../upgrade-plan.json) 的原有业务依赖顺序，仅执行尚未执行的迁移；不能把本目录全部脚本重新执行一遍。具体前置条件和重跑规则以各 SQL 文件为准。

2026-10-25 将 15 份独立菜单脚本从 `sql/1_init_table/`、`sql/2_ini_data/` 移入本目录；文件名、SQL 内容、SHA-256 及升级计划顺序保持不变。历史部署记录保留旧路径，通过文件名和摘要对应新路径，已经执行的迁移不因移动目录而重新执行。

全量建表文件继续包含 `sys_menu`、`user_menu_hidden`、`user_secondary_lock_menu`、`user_quick_nav` 等完整结构，不拆散新库唯一结构入口。历史银行卡字典脚本 `../2_ini_data/2026-09-26_bank_card.sql` 中夹带的菜单语句保留，避免改写历史混合脚本；后续新增菜单 SQL 使用本目录。
